# ใส่ asset ใหม่เข้าเกม

## สรุปสั้นที่สุด

1. `npm run sheet -- ไฟล์.png` → มันจะบอกว่ากริดเท่าไร และต้องประกาศอะไร
2. ถ้าขึ้นว่า **"ตรงกับ LPC พอดี"** → วางไฟล์ลงโฟลเดอร์ แล้วชี้จากข้อมูลไอเทม/มอน จบ
3. ถ้าไม่ตรง → ก๊อปบล็อก `defineLayout(...)` ที่มันพิมพ์ให้ ไปใส่ `shared/sheets.js`
   แล้วบอกชีตนั้นว่าใช้ layout ไหน

**ไม่ต้องแก้ renderer** ไม่ว่าขนาดเฟรมหรือจำนวนแถวจะเป็นเท่าไร

## รูปแบบที่ระบบรับ

### แบบมาตรฐาน (LPC)
PNG **832×1344** = 13 คอลัมน์ × 21 แถว ของเฟรม **64×64**

| แถว | ท่า | เฟรม |
|---|---|---|
| 0-3 | ร่ายเวท | 7 |
| 4-7 | แทง | 8 |
| 8-11 | เดิน (แถวแรกของแต่ละทิศ = ยืนเฉยๆ) | 9 |
| 12-15 | ฟัน | 6 |
| 16-19 | ยิงธนู | 13 |
| 20 | เจ็บ (ทิศเดียว) | 6 |

4 แถวต่อท่า = 4 ทิศ เรียง **บน · ซ้าย · ล่าง · ขวา**

### แบบอื่น
ประกาศใน `shared/sheets.js`:

```js
defineLayout('ชื่อ', {
  frame: { w: 96, h: 128 },   // ขนาดเฟรมจริง
  cols: 6, rows: 8,
  dirRows: 4,                 // 4 = มี 4 ทิศ, 1 = ทิศเดียว
  anchor: 0.82,               // เท้าอยู่ที่กี่ % ของความสูงเฟรม (ไว้จัดให้ยืนติดพื้น)
  anims: {
    walk: { row: 0, frames: 6, fps: 10 },
    slash: { row: 4, frames: 4, fps: 14 },
    // ท่าที่ไม่ได้ใส่ จะตกไปใช้ค่าของ LPC แทน ไม่พัง
  },
});
```

ท่าที่ขาดไปจะ fallback ไม่ทำให้จอพัง และถ้าขนาดไฟล์ไม่ตรงกับที่ประกาศ
คอนโซลจะเตือนครั้งเดียวต่อไฟล์ พร้อมบอกว่าคาดหวังเท่าไร

### มอนสเตอร์จากชีตวาด (Blue Slime เป็นตัวแรก)

ชีตมอนสเตอร์หนึ่งแผ่น = ท่าละหนึ่งแถว (IDLE WALK RUN ATTACK HIT DEATH SPAWN)
บนพื้นหลังสี ตัดด้วย `python3 tools/slice-mob.py <ชื่อ> [preview.png]`:

1. เพิ่มรายการใน `MOBS` ของสคริปต์ — ช่วงแถว (บน ล่าง จำนวนเฟรม), ตัวแยกสีตัว
   ออกจากพื้น (`solid`), ด้านที่ภาพหัน, และขนาดบนจอ (`show`)
2. สคริปต์หา "ตัว" ของแต่ละเฟรม แล้วเก็บฟอง/น้ำกระเซ็นที่ลอยอยู่เข้าตัวที่ใกล้สุด
   วางทุกเฟรมบนเส้นเท้าเดียวกัน เขียน `assets/mob/<ชื่อ>.webp` และ `shared/data/mobart.js`
3. ในข้อมูลมอนสเตอร์ใช้ `sprite: { kind: 'frames', key: '<ชื่อ>' }`

ชีตที่มีพื้นโปร่งใสจริง (เช่น Mushroom) ใส่ `'alpha': True` แทนตัวแยกสี: สคริปต์ใช้ความโปร่งใส
ของภาพเอง หาตัวแต่ละเฟรมจากส่วนที่หนา แล้วแบ่งคอลัมน์ครึ่งทางระหว่างตัว ใบไม้/ฝุ่นที่ลอยแยก
ตกเป็นของเฟรมที่มันอยู่กลาง แถว SKILL เล่นเมื่อมอนใช้ `burst` (สกิลพื้นที่: เตือนเป็นวงก่อน
แล้วระเบิดรอบตัว ใครยังอยู่ในวงโดน) หรือ `charge` (ม้วนตัวพุ่งชน: เตือนเป็นเลนก่อน แล้วกลิ้งตามเลน
ชนทุกคนในเลนครั้งเดียว) มอนที่บินได้ใส่ `sprite.fly` (ลอยสูงเหนือเงากี่พิกเซล) และ `sprite.lunge`
(พุ่งเข้าแทงแล้วถอยกลับกี่พิกเซลตอนโจมตี) ชีตที่มีแถว FLY/MOVE ให้ตั้งชื่อเป็น walk/run

มอนสายเวท (Forest Spirit เป็นตัวแรก): `shot` ยิงกระสุนที่บินไปหาเป้า ดาเมจลงตอนกระสุนถึง
(`lead` = มิลลิวินาทีที่ปล่อยมือในท่าโจมตี, `speed` = พิกเซลต่อวินาที), `kite` = ถ้าเป้าเข้ามาใกล้กว่านี้
มันจะถอยระหว่างรอยิงนัดถัดไป, `burst.at: 'target'` = วงเตือนขึ้นใต้เท้าผู้เล่นแทนรอบตัวมอน
และ `burst.root` = ตรึงคนที่โดนไว้กี่มิลลิวินาที เอฟเฟคที่วาดอยู่บนชีต (ลูกเวท รากไม้) ตัดเป็นแถบแยก
`assets/mob/<key>_fx.webp` ด้วย `fx` ใน MOBS ส่วนแถวที่มีของอื่นวาดอยู่ข้าง ๆ ใส่ช่วงคอลัมน์ของแถวนั้นได้
และแถวที่เฟรมท้าย ๆ ไม่มีตัว (ใบไม้ปลิว) ใส่ตำแหน่งตัดเองได้

มินิบอส (Alpha Wolf เป็นตัวแรก) มีแถวท่าของตัวเองแทน SKILL แถวเดียว: `leap` (วงเตือนที่เท้าผู้เล่น
กระโดดข้ามไปลงตรงนั้น, `sprite.hop` = ความสูงโค้งกระโดด), `howl` (วงรอบตัว คนที่ยังอยู่ในวงช้าลง
และมอนตีแรงขึ้นชั่วคราว) และ `enrage` (เลือดต่ำกว่า `enrage.at` ครั้งเดียว ตีแรงขึ้น เร็วขึ้น
มีออร่าแดง) ป้ายชื่อแถวบนชีตที่อยู่ทับแถวตัดออกด้วย `blank` ใน MOBS ส่วนของแถวข้าง ๆ ที่ยื่นเข้ามา
ในแถวหนึ่งตัดออกด้วยรายการสี่เหลี่ยมท้ายช่วงคอลัมน์ของแถวนั้น

บอส (Ancient Tree Guardian เป็นตัวแรก): `burst` เป็นรายการได้ แต่ละท่ามี cooldown ของตัวเอง ไม่ออกซ้อนกัน
แต่ละท่าเลือกแถวท่าเองด้วย `anim` (เช่น `spike`, `tornado`) และตีหลายครั้งได้ด้วย `pulses`/`gap`
ส่วน `calls` เรียกมอนตัวช่วย (ต้นกล้า) มาฟื้นเลือดบอสตาม `mend` ของตัวช่วยจนกว่าจะถูกตัด
ต้นกล้าตัดจากแถว SKILL 2 ของชีตเดียวกันเป็นมอนอีกตัว (`reverse` เล่นแถวย้อนกลับเป็นท่าตาย)

เซิร์ฟเวอร์ส่ง `run` ตอนไล่ล่าและ `spawn` ตอนเกิดใหม่ให้มอนแบบนี้ ท่า HIT
เล่นเมื่อโดนตีระหว่างที่ไม่ได้โจมตี และ DEATH เล่นเป็นซากชั่วครู่แล้วจางหายไป

**ชีตของดรอป** (`assets/ui/source/*_drops.png` ภาพโปร่งใส ทุกชีตรวมอยู่ในไฟล์เดียว เพิ่มชีตใน `SHEETS`) ตัดด้วย
`python3 tools/slice-drops.py` เป็นไฟล์เดียว `assets/ui/drops.webp` + `shared/data/dropart.js`:
ไอคอนไอเทม, แถวตกลงพื้น (เจล/ผลึก/ทอง), กองบนพื้นตามจำนวน (4 ขนาด) และวงหมุนตอนเก็บ
ไอเทมที่ใช้ชีตนี้ใส่ `art: 'drops#<ช่อง>'` กับ `loot: 'jelly' | 'crystal'` (ออรัมใช้แถวทองเอง)
ของที่เพิ่งตก (เซิร์ฟเวอร์ส่ง `age` มาให้) จะเล่นท่าตกก่อน แล้วค่อยนอนเป็นกองตามจำนวน;
ของที่หายไปข้างตัวเราเล่นวงหมุนเก็บ (สีฟ้าหรือสีทอง)

ชั้นที่มี: `body eyes hair head torso legs feet hands belt offhand weapon`

**ชี้จากข้อมูล** — ไอเทมใน `shared/data/items.js`:
```js
sprite: { layer: 'torso', key: 'ชื่อไฟล์', gendered: true }
sprite: { layer: 'weapon', key: 'ชื่อไฟล์', gendered: true, tint: '#f2d79a' }
```
`tint` ย้อมสีทั้งชีตครั้งเดียวแล้วแคชไว้ — ใช้ทำของระดับสูงให้ดูต่างโดยไม่ต้องวาดใหม่

### อาวุธแปดคลาสใหม่ยังยืมศิลป์เก่าอยู่

ชนิดอาวุธขยายจาก 4 เป็น 12 ตามชีต แต่ศิลป์ของแปดคลาสใหม่ยังไม่มา ของใหม่
ทุกชิ้นจึงชี้ไปที่ไฟล์ที่มีอยู่แล้ว **พร้อม `tint` ที่บอกว่ามันควรเป็นสีอะไร**
เพื่อไม่ให้ใครถืออาวุธล่องหน ตารางนี้คือรายการที่ต้องแก้เมื่อชีตจริงมาถึง —
แก้ `key` อย่างเดียว ชิ้นละบรรทัด

| คลาส | ยืม `key` | ชื่อไฟล์ที่ควรจะเป็น |
|---|---|---|
| sword | `dagger` | `weapon/<เพศ>/sword.png` |
| greatsword | `dagger` | `weapon/<เพศ>/greatsword.png` |
| dagger | `dagger` | ตรงอยู่แล้ว |
| axe | `dagger` | `weapon/<เพศ>/axe.png` |
| knuckle | `dagger` | `weapon/<เพศ>/knuckle.png` |
| throwing | `dagger` | `weapon/<เพศ>/throwing.png` |
| staff | `wand` / `steelwand` | `weapon/<เพศ>/staff.png` |
| wand | `wand` / `steelwand` | ตรงอยู่แล้ว |
| special | `dagger` / `steelwand` | `weapon/<เพศ>/special.png` |

โล่ (`shield`) ใช้ชั้น `offhand` อยู่แล้ว ไม่ต้องยืม

### ห้าช่องสวมใส่ใหม่ก็ยืมเหมือนกัน

| ช่อง | ตอนนี้วาดยังไง | ชื่อไฟล์ที่ควรจะเป็น |
|---|---|---|
| `armor` | ยืมชั้น `torso` (`leather` `chain` `plate`) | `armor/<เพศ>/<ชื่อ>.png` |
| `cloak` | วาดด้วยโค้ด `apparel.js` — `cloak: { style }` | `back/<เพศ>/<ชื่อ>.png` |
| `scarf` | วาดด้วยโค้ด — `scarf: { color }` | `neck/<เพศ>/<ชื่อ>.png` |
| `glasses` | วาดด้วยโค้ด — `glasses: { style, color }` | `face/<เพศ>/<ชื่อ>.png` |
| `mask` | วาดด้วยโค้ด — `mask: { style, color }` | `face/<เพศ>/<ชื่อ>.png` |

`shared/slots.js` บอกว่าช่องไหนวาดจากชีต (`layer`) และช่องไหนวาดด้วยโค้ด (`drawn`)
พอศิลป์จริงมาถึง เปลี่ยน `drawn` เป็น `layer` แล้วใส่ `sprite` ให้ไอเทม
ฟังก์ชันใน `apparel.js` ก็เลิกใช้ไปเอง

### ชีต LPC วาดแยกตามท่า — เลือกชีตให้ตรงท่าที่อาวุธนั้นฟาด

นี่ไม่ใช่เรื่องความสวย แต่เป็นเรื่องมองเห็นหรือไม่เห็น ชีต LPC แต่ละใบวาดเฉพาะ
ท่าที่อาวุธชนิดนั้นใช้จริง ท่าที่เหลือ**ว่างเปล่า** เช่น

| ชีต | ท่าที่มีจริง |
|---|---|
| `dagger` | ยืน · เดิน · ฟัน |
| `spear` | ยืน · เดิน · แทง |
| `longspear` | **แทงอย่างเดียว** ไม่มีท่ายืนหรือเดิน |
| `wand` `steelwand` | ฟันอย่างเดียว |
| `bow` `recurvebow` `greatbow` | ยิงอย่างเดียว |

เคยพลาดมาแล้ว: ดาบใหญ่ชี้ไปที่ `longspear` ซึ่งไม่มีท่าฟัน อาวุธจึง**หายไปทั้งเล่ม**
ทุกท่า และออร่าตีบวกหายตามไปด้วย เพราะออร่าวาดจากชั้นอาวุธ — +15 กลายเป็นตัวเปล่า
ตารางไอเทมดูถูกทุกบรรทัด แต่จอว่าง

ธนูกับคทาไม่มีท่ายืนเป็นเรื่องปกติของ LPC (ธนูอยู่บนหลังจนกว่าจะยิง) กฎจึงแคบ
แต่สำคัญ: **ท่าที่คลาสนั้นฟาด ชีตต้องมี** `test/e2e/art.test.js` เปิดไฟล์ PNG จริง
แล้วนับพิกเซลเพื่อบังคับข้อนี้

### สกิลขอท่าที่อาวุธวาดไม่ได้ → ตกลงมาเป็นท่าที่วาดได้

สกิลประกาศท่าของตัวเองไว้ท่าเดียว แต่สกิลหนึ่งตัวใช้ได้หลายคลาส และศิลป์ของแต่ละ
คลาสไม่เหมือนกัน — `แทงทะลวง` เป็นท่าแทง ซึ่งชีตหอกมีแต่ชีตดาบไม่มี ขอท่าที่ชีตไม่มี
ไม่ได้แปลว่าท่าเล็กลง แต่แปลว่า**มือเปล่า** อาวุธกับออร่าตีบวกหายทั้งคู่ตลอดสกิลนั้น
ซึ่งพอดีเป็นจังหวะที่คนกำลังจ้องมันอยู่

`poseFor(anim, wclass)` ใน `shared/weapons.js` จึงตกท่าฟาดระยะประชิดที่คลาสนั้น
วาดไม่ได้ ลงมาเป็นท่าที่มันฟาดปกติ (มีดสั้นแทง → ฟัน) ส่วน `spellcast` กับ `shoot`
**ไม่ตก** เพราะ LPC ตั้งใจไม่วาดคทาตอนร่ายและไม่วาดธนูตอนยืน — นั่นคือหน้าตา ไม่ใช่รู

แต่ละคลาสประกาศ `poses` ว่าศิลป์ตัวเองมีท่าอะไรบ้าง และเทสต์เทียบคำประกาศนั้นกับ
ไฟล์ PNG จริงทุกใบ คำประกาศจึงโกหกไม่ได้และไม่ดริฟต์เวลาเปลี่ยนศิลป์

มอนใน `shared/data/monsters.js`:
```js
sprite: { kind: 'sheet', key: 'ชื่อไฟล์', tint: '#c8b9d8', scale: 1.15 }
sprite: { kind: 'blob', shape: 'spiky', color: '#8a6a4a' }   // วาดด้วยโค้ด ไม่ต้องมีไฟล์
```

## เอฟเฟคตีบวก (+1 ถึง +15)

ระดับอยู่ใน `shared/refineglow.js` ขั้นละหนึ่งเลเวล แบ่งเป็นสามช่วง:

| ช่วง | ระดับ | ชื่อ |
|---|---|---|
| ไฟ | +1 → +7 | ประกายไฟ · ถ่านแดง · เปลวอ่อน · เปลวลุก · เพลิงกล้า · เพลิงโหม · เพลิงขาว |
| สนธยา | +8 → +11 | สนธยา · ราตรีลึก · อรุณทอง · อรุณเพลิง |
| นิรันดร์ | +12 → +15 | เปลวนิรันดร์ · ดาวตก · เพลิงมังกร · เอมเบอร์ฟอลล์ |

+8 คือจุดที่ตีบวกพลาดแล้วของพัง ไฟจึงจบตรงนั้นแล้วเปลี่ยนเป็นอย่างอื่น
+15 คือเพดาน (`MAX_REFINE`) และเซิร์ฟเวอร์อ่านเพดานจากไฟล์นี้ที่เดียว

แต่ละขั้นบอกด้วยว่าตัวเองวาด overlay ชิ้นไหนบ้าง จากแปดชิ้น
`glow1 glow2 particle aura slash circle flare spark` — ใส่ศิลป์ทีละชิ้นได้

ตอนนี้ทุกระดับ **วาดด้วยโค้ด** (เอาชั้นอาวุธมาย้อมสีแล้วซ้อนแบบ additive)
ถ้าจะใส่ภาพจริง ใส่ `sheet` ลงในระดับนั้น:

```js
{ at: 5, name: 'เพลิงกล้า', ..., sheet: '/assets/fx/fire5.png', loopMs: 800 },
```

ชีตเอฟเฟคต้องวาดบนกริดเดียวกับตัวละคร (หรือประกาศ layout ของตัวเอง)
เพราะมันเล่นทับตัวละครทีละเฟรมตามท่าที่กำลังทำ — เปลวไฟจะขยับตามจังหวะฟันจริงๆ
`loopMs` คือให้ไฟวนด้วยนาฬิกาตัวเอง จะได้ลุกต่อเนื่องแม้ตัวละครยืนเฉย

**ใส่ทีละระดับได้** ระดับที่ยังไม่มีภาพจะใช้ออร่าโค้ดเหมือนเดิม
ระดับที่มีภาพแล้ว ออร่าจะเบาลงเหลือ 35% เพื่อไม่ให้ทับกันจนเละ

### แมพสนามที่วาดเป็นภาพเดียว (ทุ่งกรีนไมร์เป็นแมพแรก)

ภาพแมพ 1536×1024 = ตาราง 60×40 ช่อง (ช่องละ 25.6px ของภาพ สเกลเดียวกับเมือง)
`python3 tools/trace-field.py <ชื่อ> [overlay.png]` แยกช่องที่เดินได้จากสีของภาพ
(ทางดิน หญ้าโล่ง ไม้ของสะพาน/บันได = เดินได้; ต้นไม้ น้ำ หน้าผา หิน = ทึบ)
ปิดพื้นที่ที่เดินไปไม่ถึง แล้วเขียน `shared/data/<ชื่อ>-obstacles.js` และ `assets/maps/<ชื่อ>.webp`

- บันได สะพาน และทางที่อยู่ใต้เงาต้นไม้ สีแยกไม่ออก → กำหนดเองใน `force_open` เป็นสี่เหลี่ยม [x, y, w, h]
- ภาพ overlay: สีดำ = ทึบ, สีแดง = พื้นเดินได้แต่ถูกตัดขาด (ต้องเปิดทางเชื่อม)
- จุดวาปวางตรงที่ทางในภาพวิ่งออกขอบแมพ; จุดเกิดมอนเป็นพื้นที่แยกตามลานโล่งแต่ละแห่ง
